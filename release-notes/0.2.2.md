**Linux** — `refryt-0.2.2-x86_64.AppImage`: download, `chmod +x`, run. Or use
`scripts/appimage-install.sh install` from source for a desktop launcher entry.

**Linux, Flatpak** — `flatpak install --user https://gridoe.github.io/refryt/refryt.flatpakref`,
then `flatpak run io.github.gridoe.refryt`; updates come with `flatpak update`. The file
`refryt-0.2.2-x86_64.flatpak` installs the same build and updates from the same repo. It
needs the GNOME 51 runtime, which Flatpak offers to fetch the first time. mpv and yt-dlp are
inside. The sandbox can't see your browsers' profile folders, so "Import from a browser" is hidden
and you sign in through the app's own window; "Launch on startup" is hidden too, since a sandboxed
app can't write a login item.

**Windows** — three options for x64, and two for ARM, cross-compiled from Linux with limited testing on real Windows
hardware:
- `refryt-0.2.2-windows-x86_64-setup.exe` — a real installer (Program Files, Start Menu,
  uninstaller). Unsigned, so SmartScreen will warn on first run — expected, not a bug.
- `refryt-0.2.2-windows-x86_64.msi` — the same files as an MSI, for deployment tools or a
  silent install (`msiexec /i refryt-0.2.2-windows-x86_64.msi /qn`). It installs to the same
  folder as the setup, so use one or the other.
- `refryt-0.2.2-windows-x86_64.zip` — portable, no install: unzip and run `refryt.exe`.
  Extract the whole folder before running; the exe needs the DLLs beside it.
- `refryt-0.2.2-windows-arm64.msi` / `.zip` — a native build for Windows on ARM, not yet tested
  on ARM hardware. The x64 files also run there under emulation.

**macOS** — `refryt-0.2.2-macos-arm64.dmg`, for Apple Silicon only. Open it and drag
Refryt to Applications. It is signed ad hoc and not notarized, so
macOS will refuse to open it on the first launch. Run `xattr -cr /Applications/Refryt.app` once,
or allow it in System Settings → Privacy & Security. libmpv and yt-dlp are bundled; nothing needs
installing.

Checksums for every file are in `refryt-0.2.2-SHA256SUMS.txt`.

What changed since 0.2.1:

- **The now-playing view opens inside the window** — F opens it in the window instead of taking
  the whole screen, so on a tiling compositor it stays in its tile (#19). It has a title strip
  like the top bar, with the window buttons in their usual place and the view's own buttons in
  the middle: close, lyrics, queue and fullscreen.
- **F11 for fullscreen** — F11 opens the view fullscreen, the way F used to, and pressing it again
  goes back. In a view opened with F, F11 turns fullscreen on or off and the view stays. Esc
  closes the view in one press.
- **Queue under the cover** — on a wide window the queue opens under the cover, and the lyrics
  stay where they are. On a tall or narrow window the queue and lyrics take turns in the same
  place, and the one turned on last shows. Short windows keep at least three queue rows and
  drop the cover first.
- **Lyrics stay put** — the lyrics column has a fixed width, so changing songs no longer shifts the
  cover and lyrics around.
- **The view remembers how you left it** — lyrics on or off, queue on or off, and which one is in
  front.
- **macOS: Enter Full Screen (⌃⌘F)** — the View menu item now uses the same fullscreen as the
  rest of the app, on the current Space, instead of moving the window to a black Space of its
  own.
