**Linux** — `refryt-0.2.1-x86_64.AppImage`: download, `chmod +x`, run. Or use
`scripts/appimage-install.sh install` from source for a desktop launcher entry.

**Linux, Flatpak** — `flatpak install --user https://gridoe.github.io/refryt/refryt.flatpakref`,
then `flatpak run io.github.gridoe.refryt`; updates come with `flatpak update`. The file
`refryt-0.2.1-x86_64.flatpak` installs the same build and updates from the same repo. It
needs the GNOME 51 runtime, which Flatpak offers to fetch the first time. mpv and yt-dlp are
inside. The sandbox can't see your browsers' profile folders, so "Import from a browser" is hidden
and you sign in through the app's own window; "Launch on startup" is hidden too, since a sandboxed
app can't write a login item.

**Windows** — three options for x64, and two for ARM, cross-compiled from Linux with limited testing on real Windows
hardware:
- `refryt-0.2.1-windows-x86_64-setup.exe` — a real installer (Program Files, Start Menu,
  uninstaller). Unsigned, so SmartScreen will warn on first run — expected, not a bug.
- `refryt-0.2.1-windows-x86_64.msi` — the same files as an MSI, for deployment tools or a
  silent install (`msiexec /i refryt-0.2.1-windows-x86_64.msi /qn`). It installs to the same
  folder as the setup, so use one or the other.
- `refryt-0.2.1-windows-x86_64.zip` — portable, no install: unzip and run `refryt.exe`.
  Extract the whole folder before running; the exe needs the DLLs beside it.
- `refryt-0.2.1-windows-arm64.msi` / `.zip` — a native build for Windows on ARM, not yet tested
  on ARM hardware. The x64 files also run there under emulation.

**macOS** — `refryt-0.2.1-macos-arm64.dmg`, for Apple Silicon only. Open it and drag
Refryt to Applications. It is signed ad hoc and not notarized, so
macOS will refuse to open it on the first launch. Run `xattr -cr /Applications/Refryt.app` once,
or allow it in System Settings → Privacy & Security. libmpv and yt-dlp are bundled; nothing needs
installing.

Checksums for every file are in `refryt-0.2.1-SHA256SUMS.txt`.

**Already on the Flatpak from a downloaded file up to 0.1.14?** Those files were not linked to
the repo, so `flatpak update` never finds a new version for them. Move over once; your settings
and sign-in stay:

```
flatpak remote-add --user --if-not-exists refryt https://gridoe.github.io/refryt/refryt.flatpakrepo
flatpak install --user --reinstall refryt io.github.gridoe.refryt
```

What changed since 0.2.0:

- **Signing in works again** — since 30 October, a signed-in session could get stuck: refryt
  said it could not reach YouTube Music, came back "online" a few seconds later and failed
  again, while signed-out browsing kept working. YouTube Music's signed-in page now sends about
  18 KB of headers, more than the 16 KB the HTTP library accepted. refryt now accepts up to
  256 KB.
- **Songs start sooner when yt-dlp is needed** — yt-dlp is first asked the way YouTube's visionOS
  app asks, which skips the slow JavaScript step: about 2.4 s instead of 3.6 s per song in a
  test, with the same audio. When that fails it falls back to the full run. The quick lookup
  also checks that the stream answers before handing it to the player, so a refused stream
  goes to yt-dlp instead of failing to play.
- **A song card opens its album at that song** — clicking a song on Home opens its album with
  the song's row marked and scrolled into view. Singles open as before.
- **Song titles open their album** — a new switch in Settings > Library, off by default, makes a
  song's title in a list open its album or single. Song cards and the player bar's title always
  do.
- **Compositor window corners** — on Linux, Settings > Appearance can leave the window's corners
  to your compositor instead of the Corners setting.
- **Pause on a playing playlist** — a playlist's page shows Pause while it is playing.
- **Headers** — an album's artist is a little larger and sits evenly between the title and the
  info line. A title too long to fit shows the full name on hover. Emoji in large titles no
  longer run into the line above.
- **Tighter lists** — songs on Home and playlists in the sidebar sit closer together, with the
  same gap round the cover on every side, and Home's song rows no longer touch on hover. In the
  collapsed sidebar, the hover around a playlist is even on all sides.
